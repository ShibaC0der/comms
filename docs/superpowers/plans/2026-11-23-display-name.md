# План реализации отображаемого имени в Comms

> Для реализации по задачам используется superpowers:executing-plans или superpowers:subagent-driven-development. Шаги отмечаются флажками.

**Цель** — пользователи вводят имя при первом входе, видят имена в списке участников и могут менять своё имя.

**Архитектура** — сервер передаёт имена вместе с состоянием участников по WebSocket. Браузер сохраняет последнее подтверждённое имя в localStorage.

**Стек** — React, TypeScript, Vite, Kotlin, Ktor.

**Спецификация** — [отображаемое имя](../specs/2026-11-23-display-name-design.md).

## Зависимость

Выполнить задачи голосового этапа, которые создают маршрут `/ws`, реестр и клиент подключения, по [существующему плану](2026-11-22-stage-1-voice-plan.md). Использовать эти компоненты для списка и смены имени.

## Проверки

Проверить пустую строку после обрезки пробелов, одинаковые имена у разных участников, попытку обновить чужое имя, поздний вход после переименования и обрыв соединения до подтверждения.
