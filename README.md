# Comms

Браузерный голосовой чат для друзей. Аудио передаётся через WebRTC; сервер на Kotlin отвечает за сигналинг и управление комнатами.

## Структура проекта

- `backend/` — Kotlin + Ktor.
- `frontend/` — React + TypeScript + Vite.
- `docs/superpowers/specs/` — дизайн-спецификации.
- `docs/superpowers/plans/` — планы реализации.

## Требования для разработки

- JDK 25.
- Node.js 22.12+ и npm.

## Локальный запуск

### Backend

Из каталога `backend/` на Linux и macOS:

```bash
./gradlew test
./gradlew run
```

В PowerShell на Windows:

```powershell
.\gradlew.bat test
.\gradlew.bat run
```

Проверка сервера:

```bash
curl http://127.0.0.1:8080/health
```

Ожидаемый ответ: `OK`.

При первом запуске Wrapper скачивает Gradle 9.7.1.

### Frontend

Из каталога `frontend/`:

```bash
npm install
npm run dev
```

Открой `http://localhost:5173`.

Проверка сборки:

```bash
npm run build
```

Vite проксирует WebSocket-маршрут сигналинга `/ws` на backend.

## CI

При каждом push GitHub Actions запускает две проверки:

- `./gradlew test` в `backend/` с JDK 25.
- `npm install` и `npm run build` в `frontend/` с Node.js 22.

Результаты доступны во вкладке **Actions**, в workflow **CI**.

## Ручная проверка голоса

1. Запусти Ktor и Vite из чистого checkout. Проверь ответ `200 OK` от `/health` и заголовок Comms на `http://localhost:5173`.
2. Надень наушники, открой две вкладки и разреши микрофон в каждой. Проверь звук в обе стороны, `WebSocket: open`, одного собеседника и `connectionState: connected` в каждой вкладке. Состояния ICE и события сигналинга можно смотреть в консоли браузера.
3. Подключи третью вкладку. В каждой должны появиться два собеседника и два аудиопотока. Закрой среднюю вкладку во время разговора и проверь, что оставшаяся пара продолжает слышать друг друга. Повтори с закрытием вкладки сразу после подключения.
4. Отключись и подключись снова в каждой вкладке без перезагрузки. После выхода проверь, что захват микрофона прекращается, список собеседников очищается, а соединения закрываются. В Chromium соединения можно посмотреть в `chrome://webrtc-internals`.
5. Запрети доступ к микрофону в настройках сайта и попробуй подключиться. Должно появиться сообщение об отказе, а другие вкладки не должны увидеть нового участника.
6. Останови backend во время разговора. Участники должны увидеть ошибку соединения, `WebSocket: closed` и пустой список собеседников. Проверь, что захват микрофона прекратился.
7. Заблокируй автозапуск звука в настройках сайта или профиля браузера и подключи собеседника. При отказе `play()` проверь сообщение о причине и нажми «Включить звук».

Для захвата микрофона браузеру нужен localhost или HTTPS. Локальный прогон проверяет сигналинг, WebRTC-соединения и очистку ресурсов. Тестовый микрофон позволяет проверить RTP и запуск воспроизведения. Слышимость и качество звука проверяются с физическим микрофоном и наушниками. Проверка связи между сетями, NAT и TURN относится к этапу 2.
